# Telegram Monitor Simple

Небольшой скрипт для поиска нужных сообщений в Telegram. Читает новые сообщения в выбранных чатах, проверяет ключевые фразы и отправляет совпадения через бота.

Это упрощённая публичная версия более крупного проекта. Здесь я оставил одну понятную задачу и один основной файл: можно прочитать код, запустить и настроить под себя.

## Что умеет

- Слушать несколько заданных групп или каналов с одного аккаунта.
- Искать фразы без учёта регистра, с границами слов.
- Исключать сообщения по антисловам отдельно для каждого правила.
- Отправлять текст, название чата, сработавшие правила и ссылку на источник, если она доступна.
- Запоминать отправленные сообщения в SQLite, чтобы повторно полученное событие не создало ещё одно уведомление.

Пример: «Сниму квартиру на месяц» подходит под правило поиска жилья. Если в том же сообщении есть «предлагаем работу», правило его пропустит. Это простые текстовые условия. Они не понимают намерение человека и могут ошибаться на цитатах или смешанных сообщениях.

## Запуск

Нужен Python 3.12+ и Telegram-аккаунт с доступом к исходным чатам.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
Copy-Item config.example.json config.json
```

Заполните `.env`:

| Переменная | Что указать |
|---|---|
| `API_ID`, `API_HASH` | Данные своего Telegram API приложения |
| `BOT_TOKEN` | Токен бота для отправки результатов |
| `RESULT_CHAT_ID` | Числовой ID чата результатов |

Аккаунт должен уже иметь доступ к исходным чатам. Бот должен иметь право писать в чат результатов; для личного диалога сначала откройте его и нажмите Start. Бот отправляет результаты, а исходные сообщения читает аккаунт через Telethon.

В `config.json` замените `@your_source_group` на свои чаты и задайте правила. Вместо username можно использовать числовой ID чата, известного сессии.

```json
{
  "chats": ["@your_source_group"],
  "rules": [
    {
      "name": "Поиск жилья",
      "keywords": ["ищу квартиру", "сниму квартиру", "шукаю житло"],
      "antiwords": ["предлагаем работу", "размещение вашей рекламы"]
    }
  ]
}
```

Внутри `keywords` достаточно одной совпавшей фразы. Любая фраза из `antiwords` отменяет только своё правило. Антислова — пример настройки, а не проверенный универсальный антиспам. «Бесплатно», «аренда» или «работа» слишком широкие для общего запрета.

```powershell
.\.venv\Scripts\python.exe main.py
```

При первом запуске Telethon запросит телефон, код входа и, если включён, пароль 2FA. Авторизация сохраняется в `data/user.session`. Код входа не относится к токену бота. Запускайте команду из папки проекта; для остановки — `Ctrl+C`. После правки правил перезапустите скрипт.

## Как устроено

`Telethon → проверка фраз → aiogram → чат результатов`

`main.py` содержит всё поведение. `config.json` хранит правила, `.env` — доступы, `data/state.db` — пары ID исходного чата и сообщения. Сами тексты в SQLite не сохраняются.

Используются Python/asyncio, Telethon для получения сообщений, aiogram для Bot API и стандартный `sqlite3`. Здесь не нужны ORM, отдельный сервер базы или брокер сообщений.

## Чем отличается расширенная версия

В расширенной системе задача была шире: выделять запросы потенциальных клиентов, уменьшать шум от предложений и вакансий, сохранять прогресс при сбоях и давать оператору управлять правилами. Под эти задачи появились дополнительные решения:

| Задача | Решение в расширенной версии | Зачем понадобилось |
|---|---|---|
| Отличать запрос жилья от вакансии с жильём | Контекстные правила, словоформы и причины принятия/отклонения | Совпадения одного слова недостаточно |
| Уточнять поиск без редактирования файлов | Команды администратора, исключения, темы по правилам | Оператору проще менять критерии и читать результаты |
| Не повторять кросспост одного автора | Хеш нормализованного текста вместе с автором и правилом | Повторная реклама не должна занимать весь поток |
| Сохранять найденное при сетевой ошибке | Совпадение и запись Outbox в одной транзакции, отдельная отправка с повторами | Отправку можно повторить без повторного поиска |
| Продолжать работу после перезапуска | Постоянные курсоры, очередь, состояния попыток и cooldown | Прогресс хранится в базе, а не только в памяти |
| Изучать реальные сообщения отдельно от выдачи | Процессы сборщика и обработчика, журнал изменений в SQLite WAL | Можно остановить обработчик и продолжить сбор на том же компьютере |
| Держать ленту результатов актуальной | Проверка возраста исходного сообщения и удаление старых карточек | Оператор видит свежие запросы |

В расширенной версии основная база работает через SQLAlchemy с SQLite или PostgreSQL. Отдельный корпус использует локальную SQLite WAL. Классификация основана на правилах и конечном словаре словоформ; обученной модели и платного LLM в этой части нет.

В этой редакции я не переносил управление аккаунтами, сбор истории, корпус для исследований и сложные очереди. Цель — небольшой самостоятельный инструмент, на котором видно базовый поток от входящего сообщения до результата. Расширенная версия не входит в этот репозиторий; таблица объясняет её решения, а не обещает эти возможности в `main.py`.

## Ограничения

Скрипт обрабатывает новые входящие события после запуска. История, правки сообщений и сообщения за время отключения не догружаются. В чаты он сам не вступает. Два экземпляра с одной сессией запускать не следует.

Фразы ищутся буквально после нормализации регистра и пробелов, без склонений: «ищу квартиру» и «ищу квартиры» — разные настройки. Поиск не доказывает, что автор живой человек или потенциальный покупатель.

При временной ошибке отправка повторяется до трёх раз; пауза Bot API соблюдается. Если все попытки не удались, в журнал попадает тип ошибки, а постоянной очереди для дальнейшей доставки здесь нет. При сбое между принятой Telegram отправкой и записью в SQLite возможен дубль. Неопределённый ответ сети также может привести к повторной отправке. Уже отправленное сообщение не переотправляется после изменения правил.

Тексты уведомлений сокращаются до лимита Telegram. Ссылка на закрытый чат откроется только у тех, у кого есть доступ. Автоудаления карточек и разнесения по темам в этой версии нет.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m unittest -v
```

Проверяются фильтрация и антислова, границы фраз, настройки, ссылки, ограничение длины, сохранение отметок между открытиями SQLite и повторная отправка при временных ошибках. Это офлайн-тесты; полноценный запуск с конкретными аккаунтом и ботом нужно проверить со своими настройками.

`.env`, `config.json`, сессии и `data/` исключены из Git. В репозитории лежат только примеры с вымышленными настройками.
